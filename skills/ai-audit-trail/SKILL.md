# ai-audit-trail：AI 協作紀錄稽核封存

把 Claude Code 對話打包成可以直接交出去備查的封存包。**預設會去除個資，但保留對話與 AI 讀過的檔案內容。**

```
ai-audit-trail-exports/
├── ai-audit-trail_<UTC時間>_<id>/          ← 可提交（另有同名 .zip）
│   ├── transcript.pdf    可讀版：封面詮釋資料＋逐則對話
│   ├── transcripts/      已遮蔽個資的 JSONL（含子代理紀錄）
│   ├── manifest.json     模型、版本、時間、論文資訊、遮蔽統計、各檔 SHA-256（遮蔽前後都有）
│   ├── SHA256SUMS        全部檔案雜湊值
│   ├── SHA256SUMS.tsr    （選用）RFC 3161 可信時間戳
│   └── README.txt        給審查者的驗證說明
└── ai-audit-trail_<UTC時間>_<id>.PRIVATE/  ← 未遮蔽原始檔，只給使用者自己保存，絕不提交
```

## 什麼會被處理

| 處理方式 | 內容 |
|---|---|
| **移除** | 系統提示詞、環境與帳號／組織資訊、技能清單等系統訊息；`<system-reminder>` 區塊；推理簽章、請求遙測等內部欄位 |
| **遮蔽成 `[REDACTED:類別]`** | email（含帳號 email 的前綴片段）、家目錄中的使用者名稱、git 姓名與 email、主機名稱、組織／帳號 UUID、API 金鑰與 token、密碼、私鑰、台灣身分證字號、手機與國際電話、公開 IP、使用者用 `--redact-term` 指定的字詞 |
| **完整保留** | 使用者提問、AI 回覆、推理摘要、工具呼叫與結果、**AI 讀過的檔案內容**（除了上面那些個資樣式）、使用者附加的檔案、時間戳、模型 ID |

規則式遮蔽抓不到「在一般文字裡出現的人名、地址、病歷」這類內容，所以第 3 步要由你（Claude）人工複查。

## 執行流程

### 1. 先問清楚（一則訊息問完，全部選填）

- 論文或計畫名稱（`--paper-title`）、對應章節或用途（`--section`）、作者（`--author`）、單位（`--affiliation`）、備註（`--note`）
- **還有哪些字詞要遮蔽**（`--redact-term`，可重複）：使用者的真實姓名、學號或員工編號、合作者或受試者姓名、實驗室或單位內部代號等。程式會自動偵測帳號和電腦上的身分資訊，但真實姓名通常只有使用者自己知道，一定要問。
- 封面上的「作者」是使用者主動要放的，不會被遮蔽；但同一個名字在對話內文裡仍然會被遮蔽。

匯出範圍預設是**目前這個對話**。如果使用者要其他對話或整個專案，先執行 `--list` 讓使用者挑選，再用 `--session <ID>`（可重複）或 `--all-project`。

`--tsa`（可信時間戳）會把 SHA256SUMS 的**雜湊值**送到外部服務（預設 FreeTSA），不會送出任何對話內容。這仍然是對外傳送資料，**要先徵得使用者同意才能加**。

### 2. 執行匯出

```bash
uv run --with reportlab python "${CLAUDE_SKILL_DIR}/scripts/export_audit_trail.py" \
  --paper-title "..." --section "..." --author "..." \
  --redact-term "真實姓名" --redact-term "學號"
```

- 沒有 `uv` 的話：先執行 `python3 -m pip install --user reportlab`，再用 `python3` 直接跑腳本。
- 預設輸出到 `./ai-audit-trail-exports/`，程式會在裡面放一個 `.gitignore`，避免匯出檔被 commit。要換位置就用 `--out <資料夾>`。
- 其他選項：
  - `--max-chars N`：PDF 裡每個區塊最多顯示幾個字元，預設 20000，`0` 表示不截斷。
  - `--no-thinking`：PDF 不放推理摘要。
  - `--transcript <path>`：直接指定一個 JSONL 檔。
  - `--no-zip`：不產生 zip。
- 只有在使用者明確要求時才能用的選項：
  - `--no-redact`：不做任何遮蔽，封存包裡放完整原始檔。
  - `--no-private-copy`：不另外保存未遮蔽的原始檔。

腳本最後會印出一段 JSON，內容包含封存路徑、`.PRIVATE` 路徑、遮蔽統計（`redaction`）、PDF 和 zip 的 SHA-256，以及遮蔽前後的雜湊值。

### 3. 人工複查殘留個資（必做）

在把結果交給使用者之前，檢查**封存包**（不是 `.PRIVATE`）裡的 `transcripts/*.jsonl`：

1. 用 `grep -n` 搜尋使用者在第 1 步提供的字詞，以及你在對話中看過的個資，例如使用者的真實姓名、指導教授或同學姓名、地址、電話，確認都已經被遮蔽。
2. 快速瀏覽使用者的提問（`"role": "user"` 裡的文字），找出規則抓不到的個資，例如在一般句子裡提到的人名、地址、生日、病歷、成績等。
3. 只是**資料或研究內容本身**的東西（AI 讀過的程式碼、論文草稿、實驗數據）不要動。只處理會識別出特定個人的資訊。
4. 如果找到殘留：告訴使用者找到什麼類型、在哪裡。**不要在回覆裡完整複述那些個資**，例如寫「一個人名（出現 3 次）」就好。經使用者同意後，加上 `--redact-term` 重新匯出，產生新的封存包，再請使用者確認是否刪掉舊的那一包。
5. 使用者附加的圖片或截圖沒辦法自動遮蔽。如果有圖片，要提醒使用者自己檢查。

**絕對不要手動修改封存包裡的檔案**，否則 SHA256SUMS 就對不上了。需要修正就重新匯出。

### 4. 回報給使用者

用繁體中文簡短回報：
1. 可提交的資料夾和 zip 的路徑，以及 zip 的 SHA-256（建議使用者另外記下來，當作封存當下的指紋）。
2. 匯出了哪些對話、用了哪些模型。
3. 遮蔽統計（例如「移除 200 則系統訊息、遮蔽 email 4 處、帳號名稱 248 處」），以及第 3 步的複查結果。
4. `.PRIVATE` 資料夾的位置，並說明：**不要提交這個資料夾**，但要自己保存好。如果審查單位要求核對，可以用它證明遮蔽版的來源；它的雜湊值就是 manifest 裡的 `original_sha256`。
5. 驗證方法：在封存資料夾執行 `shasum -a 256 -c SHA256SUMS`。
6. 如果有申請時間戳，附上取得的時間；如果申請失敗，照實說明原因。

## 注意事項

- **紀錄只到匯出那一刻為止**。建議在對話結束前最後一步再匯出。匯出這個動作本身也會被記在紀錄裡，這是正常的。
- **Claude Code 預設會自動清除舊的對話紀錄**（`cleanupPeriodDays`，預設 30 天）。長期研究專案建議調大這個值，或定期匯出；`.PRIVATE` 資料夾就是長期保存的原始檔。
- 遮蔽是確定性的：在同一台電腦上，用同一份原始檔和同樣的 `--redact-term`，每次輸出都一樣。所以必要時可以用 `.PRIVATE` 裡的原始檔重跑一次，證明遮蔽版確實是從原始檔產生的。
- PDF 字型缺少的字元（例如部分 emoji）會顯示成 `[U+XXXX]`，不會悄悄消失。
- 只支援 Claude Code 的對話紀錄。claude.ai 網頁版的對話請改用網頁版的資料匯出功能。
- 預設字型：macOS 用 Arial Unicode、Windows 用微軟正黑體；也可以用環境變數 `AI_AUDIT_TRAIL_FONT` 指定一個 TrueType 字型。
